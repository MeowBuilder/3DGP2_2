1. 시작 화면 및 메뉴 구현

프로그램이 시작되면 먼저 `CGameFramework`의 게임 상태(`m_GameState`)가 `GameState::MainMenu`일 때 활성화되는 전용 로직이 실행됩니다. 이 상태에서 렌더링되는 시작 화면과 메뉴 항목들은 화면 공간에 그려지는 2D 사각형 메시(`CUIRectMesh`)와 전용 텍스처를 사용하여 구현하였으며, 렌더링을 위해서는 `CUIShader`가 사용됩니다. UI 렌더링에 최적화하기 위해, `CUIShader`는 UI 요소의 2D 변환 행렬을 담는 상수 버퍼와 메뉴 버튼 텍스처를 셰이더로 전달하기 위한 단일 디스크립터 테이블(SRV)만을 갖도록 루트 시그니처를 단순하게 구성하였습니다. 픽셀 셰이더는 이 테이블의 첫 번째 레지스터(t0)를 통해 UI 텍스처를 샘플링하여 화면에 출력합니다. 또한 UI 요소들이 3D 객체에 가려지지 않고 항상 위에 그려지도록, 렌더링 시에는 깊이 테스트(Depth Test)가 꺼진 PSO(Pipeline State Object)를 사용합니다. 이 PSO에는 텍스처의 투명한 부분이 배경과 자연스럽게 섞이도록 알파 블렌딩(Alpha Blending) 상태를 설정해두었습니다.

사용자 입력은 `CGameFramework::ProcessInput()` 함수에서 처리되는데, 마우스 입력을 받아 `CScene::PickObjectByRayIntersection()` 함수를 호출하여 현재 마우스 커서 아래에 있는 UI 객체를 감지합니다. 감지된 객체가 메뉴 버튼일 경우, 해당 `CGameObject`의 `CMaterial`이 가진 텍스처를 기본 상태(`DefaultTexture`)에서 하이라이트 상태(`HoverTexture`)로 교체하여 사용자에게 시각적인 피드백을 제공합니다. 마우스 클릭이 감지되면 `CGameFramework::SetGameState(GameState::InGame)`를 호출하여 게임의 주 로직이 실행되는 `InGame` 상태로 전환하며, `FrameAdvance()` 함수 내에서는 이 `m_GameState` 값을 확인하여 상태에 맞는 렌더링 로직을 수행하도록 분기 처리합니다.

2. 게임 세계 구성과 주요 렌더링 기법

게임 세계는 `CScene` 클래스를 중심으로 구성되며, `BuildObjects()` 함수에서 헬리콥터, 지형, 건물 등 게임에 등장하는 모든 `CGameObject`들이 생성되어 관리됩니다. 전체 3D 월드 렌더링을 효율적으로 처리하기 위해, `CScene`은 렌더링에 필요한 거의 모든 종류의 리소스를 미리 정의하는 매우 복잡하고 큰 '마스터' 루트 시그니처(`m_pd3dGraphicsRootSignature`)를 생성하여 사용합니다. 이 루트 시그니처에는 카메라의 뷰/투영 행렬과 조명 정보를 담는 상수 버퍼(CBV)가 레지스터 b1에 바인딩되어 있고, 오브젝트별 월드 변환 행렬을 위한 상수 버퍼, 그리고 다수의 디스크립터 테이블이 포함되어 있습니다. 이 테이블들을 통해 지형의 여러 텍스처, 객체의 기본 텍스처(알베도 맵, t24), 법선 맵, 스카이박스 텍스처 등을 모두 셰이더에 전달하는 구조입니다. 이처럼 하나의 거대한 루트 시그니처를 사용함으로써, 대부분의 3D 오브젝트를 그릴 때 파이프라인 상태 변경을 최소화하며 렌더링을 수행할 수 있습니다.

법선 맵핑의 경우, `CStandardShader`를 사용하는 일반 불투명 객체들은 깊이 테스트와 깊이 쓰기가 모두 활성화되고 블렌딩은 꺼진 기본 PSO를 사용합니다. `CMaterial`에 법선 맵이 할당되어 있다면, 픽셀 셰이더는 마스터 루트 시그니처를 통해 전달된 법선 맵 텍스처를 샘플링하여 표면의 사실적인 요철을 표현하며, 이 계산을 위해 정점 셰이더에서는 TBN 행렬을 구성하여 조명과 뷰 벡터를 탄젠트 공간으로 변환하는 과정을 거칩니다.

지형 및 빌보드 중 나무와 풀 같은 식생은 `CBillboardObject`로 표현됩니다. 빌보드 렌더링 시에는 `CBillboardShader`가 사용되는데, 이 셰이더에 연결된 PSO는 기하 셰이더(Geometry Shader)를 사용하도록 설정되어 있습니다. 기하 셰이더는 정점 하나를 입력받아 카메라를 향하는 사각형을 생성하고, 픽셀 셰이더는 이 사각형에 나무 텍스처를 입힙니다. 이때 텍스처의 투명한 영역이 렌더링되지 않도록 알파 테스트(Alpha Test)가 활성화된 PSO 상태를 사용하였습니다.

반사 효과는 `CMirrorObject`의 평면을 기준으로 반사된 시점의 장면을 별도의 렌더 타겟 텍스처에 먼저 렌더링하는 방식으로 구현됩니다. 이후 본 렌더링 패스에서 `CMirrorObject`를 그릴 때, `CMirrorShader`의 픽셀 셰이더가 마스터 루트 시그니처를 통해 이 반사 텍스처를 샘플링하여 반사된 상을 표현합니다. 반사된 상과 거울 표면을 자연스럽게 혼합하기 위해, `CMirrorShader`의 PSO는 반투명 알파 블렌딩 상태가 활성화되어 있습니다.

물 표면의 애니메이션은 셰이더를 통해 구현되었습니다. `CScene`에서는 매 프레임 경과 시간(`fTimeElapsed`)을 사용하여 텍스처 좌표를 스크롤하는 변환 행렬(`m_xmf4x4WaterAnimation`)을 갱신합니다. 이 행렬은 루트 파라미터 14번을 통해 상수 버퍼로 GPU에 전달되고, `VSTerrainWater` 버텍스 셰이더는 이 행렬을 이용해 물 메시의 UV 좌표를 변환합니다. `PSTerrainWater` 픽셀 셰이더는 이렇게 동적으로 변환된 UV 좌표를 사용하여 여러 장의 물 텍스처(t6, t7, t8 레지스터에 바인딩된 기본, 노멀, 거품 텍스처)를 각기 다른 속도로 샘플링하고 혼합합니다. 이 과정을 통해 자연스럽게 흐르고 일렁이는 듯한 물 표면 효과를 만들어냅니다.

1인칭 시점에서 플레이어 기체의 조종석 등을 반투명하게 렌더링하기 위해 `CPlayerShader`에 특별한 PSO가 사용됩니다. 이 PSO는 `D3D12_BLEND_SRC_ALPHA`와 `D3D12_BLEND_INV_SRC_ALPHA`를 사용하는 표준 알파 블렌딩을 활성화하여, 조종석 텍스처의 알파 값을 기준으로 월드 화면과 자연스럽게 혼합되도록 합니다. 특히 중요한 점은, 이 PSO가 깊이 테스트는 수행하지만 깊이 버퍼에 쓰기(`DepthWriteMask = ZERO`)는 비활성화한다는 것입니다. 이를 통해 조종석이 다른 3D 오브젝트와의 앞뒤 관계는 올바르게 처리하면서도, 조종석 자체의 깊이 값이 멀리 있는 배경의 렌더링을 방해하는 Z-fighting 현상을 방지하여 깔끔한 1인칭 뷰를 구현합니다.

3. 게임 UI 구현

인게임 UI는 점수, 플레이어 속도 등을 `CScene` 클래스 내에서 직접 관리하며 실시간으로 표시합니다. 예를 들어 플레이어의 속도계는 `m_pSpeedDigits`라는 `CGameObject` 배열로 표현되며, `UpdatePlayerSpeedUI()` 함수는 플레이어의 현재 속도에 맞춰 각 숫자 `GameObject`의 UV 좌표를 변경하는 방식으로 숫자를 갱신합니다. UI 렌더링은 3D 월드 렌더링이 모두 끝난 후, `CScene::Render()` 함수의 마지막 단계에서 수행됩니다. 이때 커맨드 리스트에는 UI 전용 루트 시그니처와 PSO가 바인딩됩니다. 이 루트 시그니처는 3D 월드용 마스터 루트 시그니처보다 훨씬 간단하며, UI 텍스처(폰트, 아이콘 등)를 셰이더 레지스터 t0로 전달하는 역할에 집중합니다. 또한, 사용되는 PSO는 3D 장면에 가려지지 않고 항상 위에 그려지도록 깊이 테스트를 비활성화하고, 아이콘과 숫자 배경의 투명도를 처리하기 위해 알파 블렌딩을 활성화한 상태로 설정되어 있습니다.

4. 충돌 검사와 절두체 컬링

충돌 검사는 각 `CGameObject`가 가진 `m_WorldAABB`(World-space Axis-Aligned Bounding Box)를 이용하여 CPU에서 수행됩니다. `Animate()` 함수가 호출되어 월드 변환 행렬이 갱신될 때마다 `m_WorldAABB`가 새로 계산되고, 게임 로직에서는 이 바운딩 박스들의 `Intersects()` 메서드를 호출하여 충돌 여부를 판별합니다. 이 과정은 전적으로 CPU 연산이므로, 루트 시그니처나 PSO 같은 GPU 파이프라인 상태와는 직접적으로 연동되지 않습니다. 충돌 검사 결과는 렌더링할 오브젝트 목록을 결정하는 데 사용될 뿐, GPU의 렌더링 상태 자체를 변경하지는 않습니다. 디버깅 목적으로 `m_bRenderAABB` 플래그를 true로 설정하면, 각 객체의 바운딩 박스를 `CStandardShader`와 기본 PSO를 사용하여 화면에 직접 그릴 수 있도록 구현되었습니다.

절두체 컬링은 현재 구현되어 있지 않지만, `m_WorldAABB`가 이미 준비되어 있으므로, 향후 `CScene::Render()` 함수에서 각 객체를 그리기 전에 카메라의 절두체와 `m_WorldAABB`의 교차 검사를 수행하여 보이지 않는 객체에 대한 드로우 콜을 CPU 레벨에서 미리 제거하는 방식으로 최적화할 수 있는 구조적 기반은 마련되어 있습니다.

5. 폭발 효과(Effect) 구현

폭발 효과는 `CExplosionObject` 클래스를 통해 오브젝트 풀링 방식으로 구현되었습니다. `CScene::SpawnExplosion()` 함수가 호출되면 미리 생성된 `CExplosionObject` 인스턴스가 활성화되는 구조입니다. `Animate()` 함수는 폭발의 생명주기에 따라 현재 표시할 스프라이트 프레임(`m_nCurrentFrame`)을 계산하고, 이 값은 마스터 루트 시그니처에 정의된 상수 버퍼를 통해 셰이더로 전달됩니다. `m_pExplosionShader`의 픽셀 셰이더는 이 프레임 번호를 이용해 8x8 사이즈의 폭발 스프라이트 시트 텍스처에서 적절한 영역을 샘플링하여 렌더링합니다. 폭발 효과는 여러 파티클이 겹쳐지면서 밝게 빛나야 하므로, 렌더링 시 사용되는 PSO는 가산(Additive) 알파 블렌딩 상태가 설정되어 있습니다. 이는 픽셀 셰이더의 결과값을 프레임 버퍼의 기존 색상에 더하여 빛나는 효과를 만듭니다. 또한 파티클들이 서로 통과하며 자연스럽게 보이도록 깊이 버퍼 쓰기는 비활성화하지만, 다른 3D 오브젝트와의 가려짐 관계는 올바르게 처리하기 위해 깊이 테스트는 활성화된 PSO 상태를 사용합니다.
